<a id="description"></a>
## ОПИСАНИЕ

ACC — приложение для Android, предназначенное прежде всего для [продления срока службы батареи](https://batteryuniversity.com/article/bu-808-how-to-prolong-lithium-based-batteries).
Это достигается ограничением тока зарядки, температуры и напряжения.
Поддерживаются все решения для получения root-доступа.
Независимо от того, используется ли Magisk, установка всегда выполняется «бессистемно».

## ПРЕДУПРЕЖДЕНИЯ

ACC изменяет низкоуровневые параметры Android ([ядра](https://duckduckgo.com/lite/?q=kernel+android)), управляющие цепями зарядки.
Автор не несёт ответственности за возможные последствия использования или неправильного использования этой программы.
Используя программу, вы принимаете на себя все связанные с этим риски!

На некоторых устройствах, особенно Xiaomi, неисправный PMIC (Power Management Integrated Circuit — интегральная микросхема управления питанием) может срабатывать при использовании ACC.
Из-за этого зарядка может прекратиться.
Следите, чтобы батарея не разряжалась слишком сильно.
Настоятельно рекомендуется включить автоматическое выключение.

Подробнее см. [эту публикацию на XDA](https://forum.xda-developers.com/t/rom-official-arrowos-11-0-android-11-0-vayu-bhima.4267263/post-85119331).

[lybxlpsv](https://github.com/lybxlpsv) рекомендует загрузиться в bootloader, а затем снова запустить систему, чтобы сбросить PMIC.

- Android или ОС на его основе
- Любое решение для получения root-доступа (например, [Magisk](https://github.com/topjohnwu/Magisk))
- [BusyBox\*](https://github.com/Magisk-Modules-Repo/busybox-ndk) (только если root получен не через Magisk)
- Пользователи без Magisk могут настроить автозапуск acc, запустив `/data/adb/vr25/acc/service.sh` (или его копию/ссылку) через init.d либо совместимое приложение.
- Эмулятор терминала
- Текстовый редактор (необязательно)

\* Бинарный файл BusyBox можно поместить в `/data/adb/vr25/bin/`.
При необходимости разрешения доступа (0755) будут назначены автоматически.
Приоритет: `/data/adb/vr25/bin/busybox` > BusyBox Magisk > системный BusyBox

Другие исполняемые файлы и статические бинарники также можно поместить в `/data/adb/vr25/bin/` с соответствующими разрешениями, вместо установки в систему.

<a id="guide-de-démarage-rapide"></a>
## КРАТКОЕ РУКОВОДСТВО


0. Для выполнения всех команд и действий необходим root-доступ.

1. Установите или обновите ACC: прошейте\* ZIP-файл либо воспользуйтесь приложением-фронтендом.
Есть ещё два способа обновления: `acc --upgrade` (онлайн) и `acc --flash` (прошивка ZIP-файла).
После установки или удаления обычно перезагружать устройство не нужно.

2. [Необязательно] запустите `acc` (ассистент). Это единственная команда, которую нужно запомнить.

3. [Необязательно] выполните `acc pause_capacity resume_capacity` (по умолчанию `75 70`), чтобы задать уровни заряда, при которых зарядка будет приостанавливаться и возобновляться.

4. Если возникнут проблемы, обратитесь к разделам [устранение неполадок](#troubleshooting), [советы](#tips) и [FAQ](#frequently-asked-questions-faq).
Прежде чем сообщать об ошибке или задавать вопрос, изучите документацию: ответ часто уже есть в тексте.


<a id="notes"></a>
### Примечания

Шаги `2` и `3` необязательны, поскольку используются настройки по умолчанию.
Подробнее см. раздел [конфигурация по умолчанию](#configuration-par-défaut) ниже.
Рекомендуется попробовать шаг `2`, чтобы ознакомиться с доступными параметрами.

Параметры можно переопределять. Начните с тех настроек, смысл которых вам понятен.
Конфигурация по умолчанию уже подходит для работы.
Не пытайтесь настроить всё подряд — если только точно не знаете, что делаете.

Удаление: выполните `acc --uninstall` или прошейте\* `/data/adb/vr25/acc-data/acc-uninstaller.zip`.

ACC также работает в некоторых средах recovery.
Если ZIP-файл не прошит повторно, потребуется ручная инициализация.
Команда инициализации: `/data/adb/vr25/acc/service.sh`.

## СБОРКА И/ИЛИ УСТАНОВКА ИЗ ИСХОДНОГО КОДА


<a id="dépendances-construction"></a>
### Зависимости для сборки

- git, wget или curl
- zip


<a id="construire-des-tarballs-et-des-zips-flashables"></a>
### Сборка tar-архивов и прошиваемых ZIP-файлов

1. Скачайте и распакуйте исходный код: `git clone https://github.com/VR-25/acc.git`
или `wget  https://github.com/VR-25/acc/archive/master.tar.gz -O - | tar -xz`
или `curl -L#  https://github.com/VR-25/acc/archive/master.tar.gz | tar -xz`

2. Выполните `cd acc*`

3. Выполните `sh build.sh` (или дважды щёлкните `build.bat` в Windows 10, если установлен WSL (Windows Subsystem for Linux) с zip)


<a id="notes-1"></a>
#### Примечания

- `build.sh` автоматически задаёт или меняет `id=*` в файлах `*.sh` и `update-binary`.
Полный список выполняемых задач см. в `framework-details.txt`.
Чтобы пропустить создание архивов, запустите скрипт сборки с произвольным аргументом (например, `bash build.sh h`).
- Чтобы обновить локальный исходный код, выполните `git pull --force` или скачайте его заново (с помощью wget/curl), как описано выше.


<a id="installer-depuis-la-source-locale-ou-github"></a>
### Установка из локального исходного кода или GitHub

- `[export installDir=<родительский каталог установки>] sh install.sh` устанавливает acc из распакованного исходного кода.

- `sh install-online.sh [-c|--changelog] [-f|--force] [-k|--insecure] [-n|--non-interactive] [%родительский каталог установки%] [commit]` скачивает и устанавливает acc с GitHub, например: `sh install-online.sh dev`.
Порядок аргументов не имеет значения.
При обновлении, если `%родительский каталог установки%` не указан, используется текущий/исходный каталог.

- `sh install-tarball.sh [ID модуля, по умолчанию: acc] [родительский каталог установки (например, /data/data/mattecarra.accapp/files)]` устанавливает tar-архив (acc*gz) из каталога со скриптом.
Архив должен находиться в том же каталоге и быть скачан с GitHub: https://github.com/VR-25/acc/archive/$commit.tar.gz (примеры commit: master, dev, v2020.5.20-rc).


<a id="notes-2"></a>
#### Примечания

- `install-online.sh` — аналог команды `acc --upgrade`.

- Каталоги установки по умолчанию в порядке приоритета: `/data/data/mattecarra.accapp/files/` (приложение ACC, только если Magisk не установлен), `/data/adb/modules/` (Magisk) и `/data/adb/` (другие решения для root-доступа).

- Аргументы и параметры необязательны.
Исключение — `--non-interactive` для приложений-фронтендов.

- Параметр `--force` скрипта `install-online.sh` необходим для переустановки и отката версии.

- Если доступно обновление, команда `sh install-online.sh --changelog --non-interactive` выводит код версии (целое число) и URL журнала изменений (строку).
В интерактивном режиме дополнительно выводится запрос на скачивание и установку обновления.

- Также см. раздел [Команды терминала](#commandes-du-terminal) > `Коды выхода` ниже.


### Сборка/развёртывание WebUI (`index.html`)

Для сборки или live-развёртывания WebUI без упаковки полного zip модуля:

#### Требования
* **Node.js**: `18.0.0+` (рекомендуется Node.js `20+` LTS).
* **ADB и root-доступ** *(требуются только при использовании флага `-d` / `--deploy`)*:
  * Включите **USB Debugging** в настройках разработчика Android.
  * **Проводное подключение (USB)**: подключите устройство по USB и подтвердите запрос отладки на телефоне. Выполните `adb root` или убедитесь, что root-менеджер предоставил доступ Android Shell (com.android.shell).
  * **Беспроводное подключение (Wi‑Fi)**:
    1. Включите **Wireless Debugging** в настройках разработчика.
    2. Выполните сопряжение и подключение устройства (`adb pair <ip>:<port>` и `adb connect <ip>:<port>`).
  * *Примечание для беспроводного ADB*: убедитесь, что телефон находится в той же локальной сети, что и ПК.
  * Файлы передаются через staging (`/data/local/tmp/`) и затем перемещаются в нужное место через `su`.

#### Сборка/развёртывание

1. Запустите скрипт сборки с флагом WebUI из корня репозитория:

    - **Linux / macOS**:
      ```bash
      chmod +x build.sh

      # Собрать bundle WebUI (в output: install/webroot/index.html)
      ./build.sh -w
      # или
      ./build.sh --webui

      # Собрать И автоматически отправить на подключённое устройство (через USB или Wireless ADB)
      ./build.sh -d
      # или
      ./build.sh --deploy
      ```

    - **Windows (Command Prompt / PowerShell)**:
      ```cmd
      # Собрать bundle WebUI
      build.bat -w
      # или
      build.bat --webui

      # Собрать И отправить на устройство
      build.bat -d
      # или
      build.bat --deploy
      ```
      (*Или через Git Bash/WSL напрямую*: `bash build.sh -w/-d` или `bash build.sh --webui/--deploy`)

2. **Расположение результатов**:
   - Локальный артефакт сборки: `install/webroot/index.html`
   - Активное расположение на устройстве (при использовании `-d/--deploy`): `/data/adb/modules/acc/webroot/index.html`

```
# ХОРОШО, НО ЧТО ИМЕННО ОЗНАЧАЕТ КАЖДАЯ ИЗ ЭТИХ ПЕРЕМЕННЫХ?

# configVerCode #
# Проверяется при обновлении, чтобы определить, нужно ли обновить конфигурацию. НЕ ИЗМЕНЯТЬ.

# shutdown_capacity (sc) #
# Если батарея разряжается, её ёмкость/voltage_now_millivolts <= sc и телефон работает не менее 15 минут, демон acc выключает его, чтобы замедлить разряд и защитить батарею от повреждений из-за напряжения ниже рабочего диапазона.
# Значение sc=-1 отключает эту функцию.

# cooldown_capacity (cc) #
# Уровень ёмкости/voltage_now_millivolts, при котором начинается цикл охлаждения.
# Цикл уменьшает нагрузку на батарею, вызванную длительным воздействием высокой температуры и высокого напряжения зарядки.
# Для этого зарядка периодически приостанавливается на несколько секунд (подробнее ниже).

# resume_capacity (rc) #
# Уровень ёмкости или voltage_now_millivolts, при котором зарядка возобновляется.

# pause_capacity (pc) #
# Уровень ёмкости или voltage_now_millivolts, при котором зарядка приостанавливается.

# capacity_sync (cs) #
# На некоторых устройствах, особенно Google Pixel, показания ёмкости батареи в Android и ядре могут различаться.
# capacity_sync заставляет Android показывать фактическую ёмкость батареи, сообщаемую ядром.
# Обычно accd автоматически обнаруживает и исправляет это расхождение.
# Этот параметр переопределяет автоматическое поведение.
# Кроме того, он не позволяет Android получать показания ёмкости ниже 2%, так как некоторые системы выключаются до того, как заряд достигнет 0%.

# capacity_mask (cm) #
# Подразумевает включение capacity_sync.
# Заставляет Android сообщать "capacity = capacity * (100 / pause_capacity)", маскируя ограничения ёмкости (по сути, это усиленная версия capacity_sync).
# Также не позволяет Android получать показания ёмкости ниже 2%, так как некоторые системы выключаются до того, как заряд достигнет 0%.

# cooldown_temp (ct) #
# Температура (°C), при которой начинается цикл охлаждения.
# Цикл охлаждения замедляет износ батареи за счёт снижения температуры устройства.
# Подробнее см. описание cooldown_capacity.

# max_temp (mt) #
# mtp или max_temp_pause #
# Эти параметры работают вместе и НЕ связаны с циклом охлаждения.
# При достижении max_temp (°C) зарядка приостанавливается на max_temp_pause (секунд).
# В отличие от цикла охлаждения, который снижает нагрузку и от высокой температуры, и от высокого напряжения, эта функция предназначена ТОЛЬКО для снижения нагрузки из-за высокой температуры.
# Хотя это отдельные функции, данный параметр дополняет цикл охлаждения при экстремально высокой температуре окружающей среды.

# shutdown_temp (st) #
# Выключить систему, если температура батареи >= этого значения.

# cooldown_charge (cch) #
# cooldown_pause (cp) #
# Эти два параметра задают интервалы цикла охлаждения (в секундах).
# Если значения не заданы, цикл отключён.
# Рекомендуемые значения: cch=50 и cp=10.
# Если зарядка стала медленнее желаемого, попробуйте cch=50 и cp=5.
# Обратите внимание: cooldown_capacity и cooldown_temp можно отключить по отдельности, задав значения, которые обычно недостижимы.

# cooldown_custom (ccu) #
# Если cooldown_capacity и/или cooldown_temp вам не подходят, используйте этот параметр.
# Он имеет приоритет над обычными настройками цикла охлаждения.

# cooldown_current (cdc) #
# Вместо периодической приостановки зарядки на этапе охлаждения ограничивать максимальный ток зарядки (например, до 500 мА).

# reset_batt_stats_on_pause (rbsp) #
# Сбрасывать статистику батареи после приостановки зарядки.

# reset_batt_stats_on_unplug (rbsu) #
# Сбрасывать статистику батареи, если зарядное устройство отключено на несколько секунд.

# reset_batt_stats_on_plug (rbspl) #
# Сбрасывать статистику батареи, если зарядное устройство подключено на несколько секунд.

# charging_switch (s) #
# Если параметр не задан, acc перебирает базу и выбирает первый работающий переключатель/набор переключателей, отключающий зарядку.
# Если выбранный переключатель/набор не работает, acc сбрасывает chargingSwitch и повторяет поиск.
# Если ни один переключатель не отключает зарядку, chargingSwitch сбрасывается, а acc/d завершается с кодом ошибки 7.
# Этот автоматический процесс можно отключить, добавив " --" в конец "charging_switch=...".
# Например: acc -s s="battery/charge_enabled 1 0 --"
# Команда acc -ss всегда добавляет " --".
# Значение charging_switch=milliamps (например, 0-250) включает управление зарядкой по току.
# Если задать для переключателя зарядки значение от 3700 до 4300 (милливольт), acc остановит зарядку, ограничив напряжение.
# Подробнее см. раздел советов в README.
# В отличие от обычных переключателей, этот тип никогда не сбрасывается автоматически.
# Поэтому в данном случае добавление " --" приведёт к синтаксической ошибке.
# После изменения параметра требуется перезапустить демон (автоматически выполняется командой "acc --set").

# apply_on_boot (ab) #
# Настройки, применяемые при загрузке системы или запуске/перезапуске демона.
# Флаг --exit (см. applyOnBoot=...) указывает демону остановиться после применения настроек.
# Если флаг --exit не указан, при остановке демона восстанавливаются значения по умолчанию.

# apply_on_plug (ap) #
# Настройки, применяемые при подключении зарядного устройства.
# Этот параметр нужен, поскольку некоторые файлы /sys (например, current_max) сбрасываются при повторном подключении зарядного устройства.
# При отключении зарядного устройства и остановке демона восстанавливаются значения по умолчанию.

# max_charging_current (mcc) #
# max_charging_voltage (mcv) #
# Нужно указать только значение тока/напряжения.
# Файлы управления выбираются автоматически.

# lang (l) #
# Язык acc задаётся командой "acc --set --lang" (acc -sl).
# Если значение пустое, используется английский (en).

# run_cmd_on_pause (rcp) #
# Выполнять команды* после приостановки зарядки.
# * Обычно это скрипт ("sh some_file" или ". some_file").

# amp_factor (af) #
# volt_factor (vf) #
# Множитель для преобразования единиц измерения (например, 1V = 1000000 микровольт).
# ACC может автоматически определять единицы измерения, но этот механизм не безошибочен.
# Например, при слишком низком входном токе единицы могут быть определены неверно.
# Такое случается редко.
# Не меняйте эти параметры, если всё работает нормально.

# prioritize_batt_idle_mode (pbim) #
# Если включено, приоритет получают переключатели зарядки с поддержкой режима простоя батареи.
# Используется только если charging_switch не задан.
# По умолчанию отключено из-за проблем на устройствах Samsung (store_mode) и некоторых других.

# current_workaround (cw) #
# Использовать только файлы управления током, в путях которых есть "batt" (по умолчанию: false).
# Это необходимо только в том случае, если ограничение влияет и на входной ток, и на ток зарядки.
# Попробуйте этот параметр, если низкие значения тока не работают.
# После изменения требуется выполнить "accd --init" (автоматически выполняется командой "acc --set").

# batt_status_workaround (bsw) #
# Если параметр включён, acc не только считывает POWER_SUPPLY_STATUS: когда статус батареи — "Charging", а ток находится в диапазоне от -11 до 95 мА включительно, статус считается "Idle". После вызова функции disable_charging статус считается "Discharging", если ток значительно падает.
# Такой подход значительно повышает совместимость, поскольку acc не полагается исключительно на данные POWER_SUPPLY_STATUS. На некоторых устройствах (например, Nokia 2.2) acc работает только при включённом параметре.
# Однако на устройствах, сообщающих неверные значения тока или значительные колебания тока, управление зарядкой может работать нестабильно.
# Нередко проблемы с управлением зарядкой связаны с адаптером питания.

# sched (sd) #
# Расписания команд/скриптов в следующем формате:
#
# sched="HHMM command...
# HHMM command...
# ..."
#
# Например, 3900 мВ в 22:00 и 4100 мВ в 6:00 каждый день:
# sched="2200 acc -s mcv=3900
# 0644 acc -s mcv=4100"
#
# 12-часовой формат не поддерживается.
# Каждое расписание должно быть на отдельной строке.
# Каждая строка запускается в отдельном процессе.
# Можно указывать не только команды acc — подойдёт любая команда.
#
# Команды:
#   -s|--set [sd|sched]="[+-]расписание для добавления или шаблон для удаления"
#     Например:
#       acc -s sd=-2050 (удалить расписания, соответствующие 2050)
#       acc -s sd="+2200 acc -s mcv=3900 mcc=500; acc -n "Переключено на профиль \"сон\"" (добавить расписание)
#     Примечание: "acc -s sd=" работает как аналогичные команды (восстанавливает значение по умолчанию; для расписаний это пустое значение)

# batt_status_override (bso) #
# Переопределяет статус батареи, определяемый функцией not_charging.
# Допустимые значения: Idle, Discharging (с учётом регистра) или логика, выводящая нужное значение переменной _status.
# Если задано Idle или Discharging, переменной _status присваивается это значение, когда принудительно заданный* переключатель зарядки находится в выключенном состоянии.
# Работает только с принудительно заданным переключателем зарядки (задан вручную и заканчивается на " --").
#
# Пример: переключатель "main/cool_mode 0 1" поддерживает режим простоя. Однако иногда он срабатывает недостаточно быстро (например, при быстрой зарядке). Тогда можно принудительно задать его командой acc -ss и установить batt_status_override=Idle. Когда main/cool_mode включён (0), статус _status, как обычно, определяет функция not_charging; когда он выключен (1), _status будет равен Idle, без вызова not_charging.
#
# Пользовательская логика может выглядеть так:
# batt_status_override='[ $(cat main/cool_mode) -eq 1 ] && printf Idle'

# reboot_resume (rr) #
# Перезагрузить устройство (если capacity <= resume_capacity), чтобы возобновить зарядку.
# За 60 секунд до этого отображается предупреждение, чтобы при необходимости пользователь мог отменить действие.

# discharge_polarity (dp) #
# Переопределяет автоматическое определение полярности тока.

# one-line scripts #
# Каждая строка, начинающаяся с ": ", считается однострочным скриптом.
# Это может пригодиться для разных задач, в том числе для создания постоянных профилей конфигурации (подключения файла, переопределяющего основную конфигурацию).
# Все строки со скриптами выполняются при каждой загрузке/подключении конфигурации.
# Это происходит регулярно во время работы демона и как минимум один раз при каждом запуске команды.
# Предупреждение: все файлы, используемые в однострочных скриптах, должны находиться где-нибудь в `/data/adb/`, как и файлы данных acc.

#/DC#
```

<a id="setupusage"></a>
## НАСТРОЙКА И ИСПОЛЬЗОВАНИЕ


Как следует из раздела [конфигурация по умолчанию](#configuration-par-défaut) выше, ACC готов к работе сразу после установки и практически не требует настройки или вмешательства.

Единственная команда, которую нужно запомнить, — `acc`.
Этот интерфейс командной строки вам либо понравится, либо нет.

Если вы не хотите пользоваться командной строкой, пропустите этот раздел и используйте графическое приложение-фронтенд.

Можно также изменить файл `/data/adb/vr25/acc-data/config.txt` в текстовом редакторе.
В файле конфигурации приведены инструкции по редактированию.
Его содержимое соответствует разделу [конфигурация по умолчанию](#configuration-par-défaut) выше.

```
  -l|--log [-a|--acc] [редактор] [параметры_редактора]   Показать/изменить журнал accd (по умолчанию) или acc (-a|--acc)

      acc -s pause_capacity=60 resume_capacity=55 (сокращённо: acc -s pc=60 rc=55, acc 60 55)
      acc -s "charging_switch=battery/charging_enabled 1 0" resume_capacity=55 pause_capacity=60
    Примечание: у всех свойств есть сокращённые псевдонимы; выполните "acc -c cat", чтобы посмотреть их

  -s|--set [sd|sched]="[+-](расписание для добавления или удаления)" (2050 означает 20:50)
    например,
      acc -s sd=-2050 (удалить расписание на 20:50)
      acc -s sd="+2200 acc -s mcv=3900 mcc=500; acc -n "Переключено на профиль \"ночь\"" (добавить расписание на 22:00 и показать уведомление при переключении)
    Примечание: "acc -s sd=" работает как и другие команды (восстанавливает значения по умолчанию; расписание очищается)

  -s|--set c|--current [миллиамперы|-]   Задать/показать/сбросить максимальный ток зарядки (от 0 до 9999$(print_mA))
    например,
      acc -s c (показать текущее ограничение)
      acc -s c 500 (установить "500" как максимальное значение)
      acc -s c - (восстановить значение по умолчанию)

  -sc [миллиамперы|-]   То же, что выше

  -s|--set l|--lang   Изменить язык
    например, acc -s l

  -sl   То же, что выше

  -s|--set d|--print-default [регулярное выражение egrep (по умолчанию: ".")]   Показать конфигурацию по умолчанию без пустых строк
    например,
      acc -s d (показать всю конфигурацию по умолчанию)
      acc -s d cap (показать только строки, соответствующие "cap")

  -sd [регулярное выражение egrep (по умолчанию: ".")]   То же, что выше

  -s|--set p|--print [регулярное выражение egrep (по умолчанию: ".")]   Показать конфигурацию по умолчанию без пустых строк (см. примеры выше)

  -sp [регулярное выражение egrep (по умолчанию: ".")]  То же, что выше

  -s|--set r|--reset [a]   Восстановить конфигурацию по умолчанию ("a" означает "all": настройки и файлы управления из чёрного списка; по сути, полный сброс)
      например,
      acc -s r

  -sr [a]  То же, что выше


  -s|--set s|charging_switch   Принудительно использовать указанный переключатель зарядки
    например, acc -s s

  -ss    То же, что выше

  -s|--set s:|chargingSwitch:   Показать список известных переключателей зарядки
    например, acc -s s:

  -ss:   То же, что выше

  -s|--set v|--voltage [милливольты|-] [--exit]   Задать/показать/сбросить максимальное напряжение зарядки (от 3700 до 4300$(print_mV))
    например,
      acc -s v (показать)
      acc -s v 3900 (задать)
      acc -s v - (восстановить значение по умолчанию)
      acc -s v 3900 --exit (остановить демон после применения изменений)

  -sv [милливольты|-] [--exit]   То же, что выше

  -t|--test [файл_управления1 вкл выкл [файл_управления2 вкл выкл]]   Проверить пользовательские переключатели зарядки
    например,
      acc -t battery/charging_enabled 1 0
      acc -t /proc/mtk_battery_cmd/current_cmd 0::0 0::1 /proc/mtk_battery_cmd/en_power_path 1 0 ("::" заменяет " " — только для MTK)

  -t|--test [файл]   Проверить переключатели зарядки из файла (по умолчанию: $TMPDIR/ch-switches)
    например,
      acc -t (проверить известные переключатели)
      acc -t /sdcard/experimental_switches.txt (проверить пользовательские/сторонние переключатели)

  -t|--test [p|parse]   Найти потенциальные переключатели зарядки в журнале питания (как "acc -p"), проверить их все и добавить работающие в список известных переключателей
    Включает -x, как в acc -x -t p
    например, acc -t p

  -T|--logtail   Следить за журналом accd (следовать за файлом с помощью -F)
    например, acc -T

  -u|--upgrade [-c|--changelog] [-f|--force] [-k|--insecure] [-n|--non-interactive]   Обновить/откатить версию онлайн
    например,
      acc -u dev (обновиться до последней dev-версии)
      acc -u (установить последнюю версию текущей ветки)
      acc -u master^1 -f (установить предпоследний стабильный выпуск)
      acc -u -f dev^2 (установить dev-версию, выпущенную перед предпоследней dev-версией)
      acc -u v2020.4.8-beta --force (принудительно обновить/откатить до v2020.4.8-beta)
      acc -u -c -n (если доступно обновление, показать код версии (целое число) и ссылку на журнал изменений)
      acc -u -c (то же, что выше, но с запросом на установку)

  -U|--uninstall   Полностью удалить acc и AccA
    например, acc -U

  -v|--version   Показать версию acc и код версии
    например, acc -v

  -w#|--watch#   Следить за событиями батареи
    например,
      acc -w (обновлять сведения каждые 3 секунды)
      acc -w0.5 (обновлять сведения каждые 0.5 секунды)
      acc -w0 (не ждать)


Коды выхода

  0. Истина/успех
  1. Ложь/общая ошибка
  2. Неверный синтаксис команды
  3. Отсутствует бинарный файл busybox
  4. Запущено не от имени суперпользователя
  5. Доступно обновление ("--upgrade")
  6. Обновление недоступно ("--upgrade")
  7. Не удалось остановить зарядку
  8. Демон уже запущен ("--daemon start")
  9. Демон не запущен ("--daemon" and "--daemon stop")
  10. Не сработал ни один переключатель зарядки (--test)
  11. Ток (мА) не находится в диапазоне от 0 до 9999
  12. Не удалось выполнить инициализацию
  13. Не удалось установить блокировку $TMPDIR/acc.lock
  14. ACC не может инициализироваться, так как модуль Magisk отключён
  15. Режим питания от зарядного устройства поддерживается (--test)
  16. Не удалось включить зарядку (--test)

  Журналы автоматически экспортируются ("--log --export") при кодах выхода 1, 2 и 7.


Советы

  Команды можно объединять в цепочки для расширения функциональности.
    например, заряжать 30 минут, отключить зарядку на 6 часов, зарядить до 85% и перезапустить демон
    acc -e 30m && acc -d 6h && acc -e 85 && accd

  Пример профиля
    acc -s pc=45 rc=43 mcc=500 mcv=3900
      Уровень заряда батареи будет поддерживаться в диапазоне 43-45%, ток зарядки ограничится до 500 мА, а напряжение — до 3900 мВ.
      Подходит для ночной зарядки и постоянного подключения к зарядному устройству.

  Полная документация приведена в acc -r (или --readme) (рекомендуется)
```

<a id="plugins"></a>
## ПЛАГИНЫ

Это скрипты, переопределяющие функции и некоторые глобальные переменные.
Их нужно поместить в `/data/adb/vr25/acc-data/plugins/`.
Файлы сортируются и подключаются в этом порядке.
В именах файлов не должно быть пробелов.
Скрытые файлы и файлы без расширения `.sh` игнорируются.

Существуют также _временные_ плагины (удаляются после перезагрузки и полезны для отладки): `/dev/.vr25/acc/plugins/`.
Они имеют приоритет над постоянными.

Чтобы загрузить новые или изменённые плагины, перезапустите демон.

<a id="notestips-for-front-end-developers"></a>
## ПРИМЕЧАНИЯ ДЛЯ РАЗРАБОТЧИКОВ ФРОНТЕНДОВ


<a id="basics"></a>
### Основы

Для ACC не требуется Magisk.
Подойдёт любое решение для получения root-доступа.

Используйте `/dev/.vr25/acc/acca` вместо обычной команды `acc`.
Эта версия оптимизирована для фронтендов, гарантированно доступна сразу после установки/обновления и значительно быстрее обычной `acc`.
Команда `acca --set prop1=bla prop2="bla bla" ...` выполняется асинхронно (без блокировки), поэтому несколько её экземпляров могут работать параллельно.

Предпочтительно использовать полные параметры вместо сокращений, например `--set charging_switch=` вместо `-s s=`.
Так код будет понятнее и менее загадочным.

Включайте в свои приложения описания функций и параметров ACC.
При необходимости добавляйте проверенную дополнительную информацию.
Объясняйте настройки и понятия максимально ясно и кратко.

Используйте коды выхода.
См. `НАСТРОЙКА И ИСПОЛЬЗОВАНИЕ > [Команды терминала](#commandes-du-terminal) > Коды выхода`.


<a id="installingupgrading-acc"></a>
### Установка и обновление ACC

Это должно быть просто.
Самый простой способ — прошить acc через приложение Magisk.

Также можно использовать `install.sh`, `install-online.sh` или `install-tarball.sh`.
Подробнее см. раздел [Установка из локального исходного кода или GitHub](#installer-depuis-la-source-locale-ou-github).

Разработчики также могут использовать API _updateJSON_.
Фронтенд скачивает и обрабатывает [этот JSON-файл](https://raw.githubusercontent.com/VR-25/acc/master/module.json).
Формат файла:

```
{
    "busybox": "https://github.com/Magisk-Modules-Repo/busybox-ndk",
    "changelog": "https://raw.githubusercontent.com/VR-25/acc/master/changelog.md",
    "curl": "https://github.com/Zackptg5/Cross-Compiled-Binaries-Android/tree/master/curl",
    "tgz": "https://github.com/VR-25/acc/releases/download/$version/acc_${version}_${versionCode}.tgz",
    "tgzInstaller": "https://github.com/VR-25/acc/releases/download/$version/install-tarball.sh",
    "version": "STRING",
    "versionCode": INT,
    "zipUrl": "https://github.com/VR-25/acc/releases/download/$version/acc_${version}_${versionCode}.zip"
}
```

<a id="uninstalling-acc"></a>
### Удаление ACC

Выполните `/data/adb/vr25/acc/uninstall.sh` (перезагрузка не требуется; **зарядное устройство должно быть подключено**) либо удалите модуль через приложение Magisk и перезагрузите устройство.


<a id="initializing-acc"></a>
### Инициализация ACC

В обработчике boot_completed и при запуске основной активности выполните:

`[ -f /dev/.vr25/acc/acca ] || /data/adb/vr25/acc/service.sh`

Пояснение:

Необходимо инициализировать рабочую среду ACC: обновить штатную конфигурацию зарядки (чтобы восстановить её без перезагрузки) и предварительно обработать данные для повышения эффективности.
Это выполняется ровно один раз после загрузки системы.
Если бы инициализация выполнялась только после установки/обновления, acc пришлось бы переустанавливать или обновлять после каждого обновления ядра.
Дело в том, что обновления ядра часто меняют настройки драйверов источников питания по умолчанию.

Поскольку основные исполняемые файлы acc динамические (и, как ожидается, регулярно меняются), на них создаются ссылки в `/dev/.vr25/acc/`, чтобы сохранить API.
После каждой загрузки ссылки необходимо создать заново, поскольку `/dev/` — временная файловая система.

`accd` — символическая ссылка на `service.sh`.
Если запускать service.sh каждый раз при открытии `main activity`, accd будет без необходимости перезапускаться.

Примечания

- Эта «ручная» инициализация _обязательна_ только если Magisk не установлен, и только один раз за сеанс загрузки. Magisk сам запускает service.sh вскоре после загрузки.
- Установщик ACC всегда выполняет инициализацию.


<a id="managing-acc"></a>
### Управление ACC

Как уже говорилось, фронтендам следует использовать исполняемый файл `/dev/.vr25/acc/acca`.
См. разделы [конфигурация по умолчанию](#configuration-par-défaut) и [команды терминала](#commandes-du-terminal) выше.

В описании конфигурации по умолчанию есть раздел с псевдонимами/сокращениями переменных.
С `/dev/.vr25/acc/acca --set` используйте ТОЛЬКО их!

Важно: `/dev/.vr25/acc/acca --set chargingSwitch=...` не поддерживается!
Используйте `s` или `charging_switch`.
`chargingSwitch` и все остальные переменные в стиле camelCase предназначены только для внутреннего использования (то есть относятся к закрытому API).

Не обрабатывайте файл конфигурации напрямую.
Используйте `--set --print` и `--set --print-default`.
Подробнее см. раздел [команды терминала](#commandes-du-terminal).


<a id="the-output-of---info"></a>
### Вывод команды --info

Эти данные поступают из ядра, а не от acc.
Одни ядра предоставляют больше сведений, чем другие.

Большинство строк либо не нужны (например, type — это и так очевидно), либо ненадёжны (например, health и speed).

В первую очередь обращайте внимание на:

STATUS=Charging # Charging, Discharging или Idle
CAPACITY=50 # Уровень заряда батареи, 0-100
TEMP=281 # Всегда в (ºC * 10)
CURRENT_NOW=0 # Ток зарядки (амперы)
VOLTAGE_NOW=3.861 # Напряжение зарядки (вольты)
POWER_NOW=0 # (CURRENT_NOW * VOLTAGE_NOW) (ваты)

Обратите внимание: мощность указывает, сколько энергии фактически поступает в батарею, а не сколько выдаёт адаптер.
Внешнее питание всегда преобразуется до того, как достигает батареи.


<a id="profiles"></a>
### Профили

Профили — это просто разные файлы конфигурации.
Путь к конфигурации можно передать первым аргументом исполняемому файлу `acca` и вторым — `accd`.

Примеры:

_Копирование конфигурации:_

Текущая конфигурация: `/dev/.vr25/acc/acca --config cat > /path/to/new/file`

Конфигурация по умолчанию: `/dev/.vr25/acc/acca /path/to/new/file --version` (`--version` можно заменить любым параметром и аргументами, как показано ниже.)

_Редактирование копии:_

`/dev/.vr25/acc/acca /path/to/new/file --set pause_capacity=75 resume_capacity=70` (если файл не существует, он будет создан как копия конфигурации по умолчанию.)

_Использование копии:_

`/dev/.vr25/acc/accd --init /path/to/new/file` (демон перезапускается с новой конфигурацией.)

_Возврат к основной конфигурации:_

`/dev/.vr25/acc/accd --init`


<a id="more"></a>
### Дополнительно

После изменения конфигурации перезапускать демон ACC не нужно.
Он применяет новые настройки через несколько секунд.

Есть несколько исключений:

- Для `charging_switch` (`s`) требуется перезапустить демон (`/dev/.vr25/acc/accd`).
- Для `current_workaround` (`cw`) требуется полная повторная инициализация (`/dev/.vr25/acc/accd --init`).

Эта информация также приведена в разделе [конфигурация по умолчанию](#configuration-par-défaut).

<a id="troubleshooting"></a>
## УСТРАНЕНИЕ НЕПОЛАДОК


<a id="acc--t-results-seem-inconsistent"></a>
## Результаты acc -t кажутся непоследовательными

См. «конфигурация по умолчанию > batt_status_workaround».


<a id="battery-capacity--level-doesnt-seem-right"></a>
### Уровень заряда батареи отображается неверно

Если показания уровня заряда в Android отличаются от показаний ядра, демон ACC автоматически синхронизирует их: останавливает службу батареи и каждые несколько секунд передаёт ей фактическое значение.

На устройствах Pixel расхождения в показаниях уровня заряда известны уже давно.

Если устройство выключается до полного разряда батареи, могут помочь capacity_sync или capacity_mask.
Подробнее см. раздел [конфигурация по умолчанию](#configuration-par-défaut) выше.


<a id="finding-additionalpotential-charging-switches-quickly"></a>
<a id="charging-switch"></a>
### Переключатель зарядки

По умолчанию ACC использует любой работающий [переключатель зарядки](https://github.com/VR-25/acc/blob/dev/acc/charging-switches.txt) (автоматический выбор переключателя).
Однако не всегда всё работает без проблем.

- Некоторые переключатели работают нестабильно в определённых условиях (например, при выключенном экране).

- Другие удерживают [wakelock](https://duckduckgo.com/lite/?q=wakelock).
Из-за этого батарея быстро разряжается, когда зарядка приостановлена, но устройство остаётся подключённым к зарядному устройству.

- Через несколько секунд после отключения зарядки демоном acc система снова её включает.
В результате батарея в итоге заряжается до 100%, независимо от pause_capacity.

- Также сообщалось о высокой нагрузке на процессор, которая разряжает батарею.

- В худшем случае статус батареи отображается как `discharging`, хотя она фактически заряжается.

В таких случаях нужно принудительно выбрать переключатель, который работает как следует.
Для этого:

1. Выполните `acc --test` (или `acc -t`), чтобы проверить, какие переключатели работают.
2. Выполните `acc --set charging_switch` (или `acc -ss`), чтобы принудительно задать работающий переключатель.
3. Проверьте его надёжность. Если он работает неправильно, попробуйте другой.

Поскольку не все пользователи хорошо разбираются в технике, демон ACC автоматически применяет настройки для некоторых устройств, чтобы снизить вероятность проблем с переключателями зарядки.
Они находятся в `acc/oem-custom.sh`.


<a id="custom-max-charging-voltage-and-current-limits"></a>
### Пользовательские ограничения максимального напряжения и тока зарядки

К сожалению, эти возможности поддерживаются не всеми ядрами.
Пользовательские ограничения тока поддерживаются большинством ядер (по крайней мере, в той или иной степени), а настройка напряжения встречается _исключительно_ редко.

Однако наличие файла управления напряжением/током ещё не означает, что в него можно записывать* или что функция поддерживается.

\* Одного root-доступа недостаточно.
Разрешения на уровне ядра могут запрещать запись в некоторые интерфейсы.

Иногда восстановить ток по умолчанию можно только после перезагрузки системы.
В качестве обходного решения задайте максимальный ток по умолчанию или любое достаточно большое значение (например, 9000 мА).
Не беспокойтесь о повреждении устройства: телефон будет потреблять только тот ток, который способен принять.

**ПРЕДУПРЕЖДЕНИЕ**: ограничение напряжения на некоторых устройствах приводит к отклонению уровня заряда батареи (SoC).
Однако система управления батареей постоянно выполняет самокалибровку.
Поэтому после восстановления ограничения напряжения по умолчанию она начнёт корректировать показания.

Ограничение тока, напротив, считается безопасным на всех устройствах.
Однако некоторые устройства поддерживают не любые значения тока.
Это не значит, что значения вне диапазона вызовут проблемы: они просто игнорируются.

Если низкие значения тока не работают, попробуйте задать `current_workaround=true` (параметр вступает в силу после `accd --init`).
Подробнее см. раздел [конфигурация по умолчанию](#configuration-par-défaut).

Чтобы переопределить списки файлов управления максимальным током/напряжением зарядки по умолчанию, скопируйте `acc/ctrl-files.sh` в `/data/adb/vr25/acc-data/plugins/` и измените копию.
Перед этим восстановите ограничения по умолчанию, иначе может потребоваться перезагрузка системы.
Напоминание: для загрузки новых или изменённых плагинов необходимо перезапустить демон.


<a id="diagnosticslogs"></a>
### Диагностика и журналы

Временные журналы (удаляются после перезагрузки; только файлы `.log`) хранятся в `/dev/.vr25/acc/`.
Постоянные журналы находятся в `/data/adb/vr25/acc-data/logs/`.

Команда `acc -le` экспортирует все журналы acc, а также журналы Magisk и дополнительные данные в `/data/adb/acc-data/logs/acc-$device_codename.tgz`.
Журналы не содержат персональных данных и никогда не отправляются разработчику автоматически.
Автоматический экспорт (локально) выполняется при определённых условиях (см. `НАСТРОЙКА И ИСПОЛЬЗОВАНИЕ > Команды терминала > Коды выхода`).


<a id="install-upgrade-stop-and-restart-processes-seem-to-take-too-long"></a>
### Установка, обновление и остановка/перезапуск занимают слишком много времени

Остановка демона предполагает полный откат изменений, внесённых в систему управления зарядкой.
Иногда **для этого необходимо подключить зарядное устройство**.
Это связано с ошибками ядра и/или некорректной реализацией драйверов зарядки на некоторых устройствах.
Поэтому accd всегда останавливается _корректно_, чтобы изменения гарантированно были отменены.
Опытные пользователи могут принудительно остановить accd командой `pkill -9 -f accd`.


<a id="kernel-panic-and-spontaneous-reboots"></a>
### Паника ядра и самопроизвольные перезагрузки

Файлы управления, вызывающие такие проблемы, автоматически заносятся в чёрный список (в `/data/adb/acc-data/logs/write.log` они отмечаются комментариями).


<a id="restore-default-config"></a>
### Восстановление конфигурации по умолчанию

Это может сэкономить много времени и избавить от лишних проблем.

`acc --set --reset`, `acc -sr` или `rm /data/adb/vr25/acc-data/config.txt` (аварийный вариант)


<a id="samsung-charging-always-stops-at-70-capacity"></a>
### Samsung: зарядка _всегда_ останавливается на уровне 70%

Это проблема конкретных устройств (так задумано?).
Её вызывает файл управления зарядкой _store_mode_.
Чтобы избежать этого, используйте _batt_slate_mode_.
Подробнее см. раздел [Переключатель зарядки](#charging-switch) выше.


<a id="slow-charging"></a>
### Медленная зарядка

Возможные причины:

- Ограничения тока и/или напряжения зарядки.
- Цикл охлаждения (неоптимальное соотношение времени зарядки и паузы; попробуйте 50/10 или 50/5).
- Проблемный переключатель зарядки (см. `УСТРАНЕНИЕ НЕПОЛАДОК > Переключатель зарядки`).
- Слабый адаптер питания и/или кабель.


<a id="unable-to-charge"></a>
### Не удаётся зарядить устройство

См. раздел [Предупреждения](#avertissements) выше.


<a id="unexpected-reboots"></a>
### Неожиданные перезагрузки

Неподходящие или проблемные файлы управления зарядкой могут вызывать неожиданные перезагрузки.
ACC автоматически заносит некоторые из них в чёрный список (они отмечаются символом решётки в `/data/adb/vr25/acc-data/logs/write.log`).
Иногда туда могут попасть и исправные файлы — например, если перезагрузка была вызвана другой причиной. Поэтому, если ранее работавший файл управления внезапно перестал работать, проверьте, не попал ли он в чёрный список (команда `acc -t` также показывает заблокированные переключатели).
После прекращения перезагрузок отправьте разработчику файл `write.log`.


<a id="warp-vooc-and-other-fast-charging-tech"></a>
### WARP, VOOC и другие технологии быстрой зарядки

Переключатели зарядки могут работать нестабильно с оригинальным адаптером питания.
Это не связано с acc — причина в неудачной реализации со стороны производителя устройства.
Если возникли проблемы, попробуйте другой переключатель зарядки или обычный адаптер питания (то есть медленную зарядку).
Можно также попробовать останавливать зарядку ограничением тока/напряжения.


<a id="why-did-accd-stop"></a>
### Почему остановился accd?

Чтобы выяснить причину, выполните `acc -l tail`.
Команда выведет последние 10 строк журнала демона.

Довольно часто встречается код выхода `7`: ни один переключатель зарядки не смог её отключить.
Обычно это связано с проблемами ядра (см. предыдущий подраздел — [Переключатель зарядки](#charging-switch)).
Демон останавливается по этой причине только тогда, когда acc автоматически выбирает переключатели (режим по умолчанию).
Если вручную задать работающий переключатель с помощью `acc -ss` или `acc -s s="ПЕРЕКЛЮЧАТЕЛИ ЗДЕСЬ --"`, автоматический режим отключится, и accd не остановится, даже если выбранные переключатели не смогут отключить зарядку.

<a id="tips"></a>
## СОВЕТЫ


<a id="always-limit-the-charging-current-if-your-battery-is-old-andor-tends-to-discharge-too-fast"></a>
### _Всегда_ ограничивайте ток зарядки, если батарея старая и/или быстро разряжается

Это продлевает срок службы батареи и может даже _снизить_ скорость её разряда.

Для повседневного использования хорошо подойдёт диапазон 750–1000 мА.

500 мА — разумный минимальный ток, который также поддерживается большинством устройств.

Если устройство не поддерживает пользовательские ограничения тока, используйте отдельный адаптер питания («медленную» зарядку).


<a id="current-and-voltage-based-charging-control"></a>
### Управление зарядкой по току и напряжению

Включается значением charging_switch=milliamps или charging_switch=3700-4300 (милливольты), например: `acc -s s=0`, `acc -s s=250`, `acc -s s=3700`, `acc -ss` (мастер).

По сути, файлы управления током/напряжением превращаются в _[псевдо]переключатели зарядки_.

Полезным побочным эффектом часто становится _[псевдо]режим простоя_: батарея может работать лишь как буфер питания.

Примечание: в зависимости от ядра при достижении `pause_capacity` статус зарядки может измениться на ("discharging" или "not charging") либо остаться прежним ("charging" — это не проблема).
Если статус периодически меняется, ток слишком низкий; увеличивайте его, пока проблема не исчезнет.


<a id="generic"></a>
### Общие рекомендации

Имитируйте _режим простоя батареи_ с помощью ограничения напряжения: `acc -s pc=101 rc=0 mcv=3900`.
Первые два аргумента отключают обычную функцию приостановки/возобновления зарядки.
Последний задаёт ограничение напряжения, определяющее уровень зарядки батареи.
Когда напряжение батареи достигает пика, она переходит в _[псевдо]режим простоя_.
По сути, батарея работает как буфер питания.

Похожего эффекта можно добиться настройками `acc 60 59` (проценты) и `acc 3900` (милливольты).

Ещё один способ — ограничить ток зарядки примерно до 0–250 мА (например, `acc -sc 0`).
Команда `acc -sc -` восстанавливает ограничение по умолчанию.
Можно также поэкспериментировать с `acc -s s=0` и/или `acc -s s=3700`, где файлы управления током/напряжением используются как переключатели зарядки.

Принудительное включение быстрой зарядки: `appy_on_boot="/sys/kernel/fast_charge/force_fast_charge::1::0 usb/boost_current::1::0 charger/boost_current::1::0"`


<a id="google-pixel-devices"></a>
### Устройства Google Pixel

Принудительно включить быструю беспроводную зарядку сторонними зарядными устройствами, которые должны заряжать батарею быстрее: `apply_on_plug=wireless/voltage_max::9000000`.

Это может работать не на всех устройствах Pixel.
Если не сработает, никаких негативных последствий не будет.


<a id="export-import-config"></a>
### Экспорт/импорт конфигурации

Экспорт: `acc -s > /sdcard/Download/config.txt`

Импорт: `acc -s /sdcard/Download/config.txt`

Поддерживается частичный импорт — можно поделиться только частью конфигурации (например, `acc -sp curr,volt > file`); тот, кто импортирует её, получит только эти изменения.


<a id="override-battery-mah-capacity"></a>
### Переопределение ёмкости батареи в мА·ч

«Расширенная» батарея не будет заряжаться полностью, если ядро по-прежнему использует исходное значение `charge_full_design`.
На некоторых устройствах это можно изменить. Если это относится к вашему случаю, используйте `apply_on_boot`, чтобы задать нужное значение(-я) в `/sys/class/power_supply/*/charge_full_design`.


<a id="override-broken-temperature-sensor"></a>
### Переопределение неисправного датчика температуры

Если датчик температуры батареи постоянно показывает отрицательное значение, а зарядка очень медленная или вообще не идёт, попробуйте следующее (вставьте и выполните):

`acc -c d temp_cool; acc -c a ':; for i in */temp_cool */temp_cold; do [ -f $i ] || continue; chmod a+w $i && echo "-999" > $i || :; done'`


<a id="idle-mode-and-alternatives"></a>
### Режим простоя и альтернативы

1 — Переключатель зарядки с поддержкой режима простоя (очевидно, лучший вариант).
Помните, что саморазряд всё равно происходит.
Это похоже на физическое отключение батареи.
Ожидается крайне медленный разряд.

2 — `charging_switch=0`: если ток колеблется, задайте также `current_workaround=true` (вступает в силу только после перезагрузки).
Если этот способ работает, результат будет таким же, как в `#1`.

3 — `charging_switch=3900`: работает только на устройствах с поддержкой управления напряжением.
В отличие от обычного режима простоя, напряжение будет постоянно поддерживаться на уровне 3900 мВ.
Более высокое напряжение нежелательно.
Наша цель — максимально снизить нагрузку на батарею.
Длительно поддерживать напряжение выше 3900 мВ _не рекомендуется_.

4 — `acc 3900`: сокращённая форма команды _acc 3900 3870_ (разница 50 мВ).
Она пытается поддерживать 3900 мВ без поддержки управления напряжением.
Да, это действительно работает.
Способ использует обычные переключатели зарядки и показания напряжения.

5 — `acc 45 44`: в большинстве случаев это примерно соответствует 3900 мВ.
Напряжение и ёмкость (%) не связаны линейно.
Напряжение зависит от температуры, химического состава и возраста батареи.

<a id="frequently-asked-questions-faq"></a>
## ЧАСТО ЗАДАВАЕМЫЕ ВОПРОСЫ (FAQ)


> Как сообщить о проблеме?

Создайте issue на GitHub или свяжитесь с разработчиком через Facebook, Telegram (предпочтительно) или XDA (ссылки ниже).
Всегда приводите как можно больше информации.
Приложите файл `/sdcard/Download/acc-logs-*.tgz`, созданный командой `acc -le` _сразу после_ возникновения проблемы.
Подробнее см. `УСТРАНЕНИЕ НЕПОЛАДОК > Диагностика и журналы`.


> Почему вы не добавляете поддержку моего устройства? Я жду уже целую вечность!

Во-первых, наберитесь ещё немного терпения!
Во-вторых, в некоторых системах файлы управления зарядкой устроены неочевидно: приходится разбираться глубже и порой импровизировать, а это требует времени и усилий.
Наконец, некоторые системы вовсе не поддерживают пользовательское управление зарядкой. В таком случае пробуйте разные ядра и отправляйте соответствующие журналы источников питания.
См. раздел `ЖУРНАЛЫ ИСТОЧНИКОВ ПИТАНИЯ (НУЖНА ПОМОЩЬ)`.


> Зачем, когда и как калибровать систему управления батареей?

Для современных систем управления батареей это обычно не требуется.

Однако если батарея работает хуже ожидаемого, можно попробовать процедуру, описанную на странице https://batteryuniversity.com/article/bu-603-how-to-calibrate-a-smart-battery .

Если зарядка включена и время работы системы >= 900 секунд, ACC автоматически оптимизирует производительность системы и использование батареи, принудительно запуская `bg-dexopt-job` при [перезапуске] демона один раз после загрузки.


> Я установил напряжение 4080 мВ — это примерно соответствует заряду 75%.
Но что безопаснее: продолжать зарядку или многократно включать и отключать её при достижении заданных уровней заряда?

Дело не столько в том, какой способ безопаснее.
Главное — стабильность электронов: нужно оптимизировать давление (напряжение) и протекание тока.

Если не задавать ограничение напряжения выше 4200 мВ и не оставлять телефон надолго подключённым к зарядному устройству, одного этого ограничения достаточно.
В противном случае второй способ будет полезнее, поскольку он сильнее сокращает воздействие высокого напряжения и время такого воздействия.
Одновременное использование обоих способов даст наилучший результат.
Дополнительную пользу принесёт включение цикла охлаждения.

Задумывались, почему литий-ионные батареи продаются не полностью заряженными? Обычно их заряд составляет около 40–60%. Почему?
Длительное хранение батареи полностью или почти полностью разряженной либо заряженной более чем на 70% приводит к значительной (необратимой) потере ёмкости.

Как применить всё это на практике:

Ночной/интенсивный профиль: поддерживать заряд в диапазоне 40–60% и/или напряжение около 3900 мВ.

Дневной/обычный профиль: максимальный заряд 75–80% и/или напряжение не выше 4100 мВ.

Профиль поездки: заряд до 95% и/или напряжение не выше 4200 мВ.

\* https://batteryuniversity.com/article/bu-808-how-to-prolong-lithium-based-batteries/


> Я не совсем понимаю, для чего нужны "-f|--force|--full [capacity]".

Представьте такую ситуацию:

Вы почти опаздываете на важное мероприятие.
Вспоминаете, что я украл ваш внешний аккумулятор и продал его на eBay.
Вам нужен телефон с хорошим запасом заряда.
Мероприятие продлится весь день, а посреди глуши негде будет подключиться к источнику питания.
Нужно быстро зарядить батарею как можно сильнее.
При этом вы не хотите менять конфигурацию ACC или вручную останавливать/перезапускать демон.


> Что такое DJS?

Это отдельная программа — Daily Job Scheduler (планировщик ежедневных задач).
Как следует из названия, она предназначена для планирования «задач» — в данном случае профилей/настроек acc.
В основе работы лежит запуск команд/скриптов в заданное время: один раз, ежедневно и/или при загрузке системы.


> Нужно ли устанавливать/обновлять и ACC, и AccA?

Чтобы разобраться в этом вопросе, нужно понять, что такое ACC и AccA.

ACC — это программа для Android, управляющая зарядкой.
Её можно установить как модуль приложения (например, AccA), модуль Magisk или отдельную программу. Установщик определяет путь и вариант установки, но пользователь может переопределить выбор.

Конфигурация программы хранится в обычном текстовом файле. Его можно редактировать любым текстовым редактором с root-доступом.
У ACC есть интерфейс командной строки (CLI), который по сути представляет собой набор интерфейсов программирования приложений (API). CLI/API упрощает выполнение сложных задач.

AccA — это графический интерфейс (GUI) для командной строки ACC. Его задача — упростить обычные действия.
AccA поставляется с версией ACC, которая автоматически устанавливается при первом запуске приложения.

Итак, ACC похож на полностью автономный автомобиль, в котором всё же есть руль и другие органы управления — чтобы обычный водитель мог врезаться в дерево.
Представьте AccA в виде робота-водителя, который порой предпочитает сбивать людей, а не деревья.
По разным причинам этого робота могут обновлять реже, чем автомобиль.
Регулярное обновление автомобиля радует водителя — хотя у машины, вероятно, нет никаких чувств.
Внутреннюю часть можно обновить, прошив последнюю версию ZIP-файла ACC.
Но если для этого нет веской причины, не чините то, что не сломано.


> Работает ли acc, когда Android выключен?

Нет, но такая возможность изучается.
Однако сейчас программа работает в режиме recovery.


> При отключении зарядки сразу появляется wakelock. Что делать?

Лучшее решение — принудительно выбрать переключатель зарядки, который не вызывает wakelock.
См. `УСТРАНЕНИЕ НЕПОЛАДОК > Переключатель зарядки`.
Обычно помогает настройка `resume_capacity = pause_capacity - 1`, например resume_capacity=74, pause_capacity=75.


> Что такое режим простоя и как его настроить?

Это возможность работать от зарядного устройства.
Батарея ведёт себя так, словно физически отключена от устройства.
Основной признак режима простоя — ток зарядки около 0 мА. Значение idleThreshold можно настроить вручную.

Режим простоя удобен для длительного использования устройства (например, GPS-навигации, игр, сервера). Используйте его, когда зарядное устройство должно быть подключено долго (или постоянно).

ВАЖНО: литий-ионные батареи живут дольше всего, когда их держат заряженными примерно на 40–60% (примерно 3,7–3,9 В). Тем не менее, старайтесь не использовать режим простоя выше 60% слишком часто.

Не все устройства поддерживают «нативный» режим простоя. Поэтому доступны варианты «эмуляции» режима простоя:

1. Ограничить напряжение зарядки (требуется поддержка ядра) до значения, близкого к нужному уровню заряда батареи. Чтобы избежать ложных срабатываний, определяйте значение только после того, как устройство было отключено от зарядки примерно минуту.
2. Приостанавливать/возобновлять зарядку по порогам напряжения (например, `acc 3950` удерживает напряжение в пределах 3800–3950 мВ).
3. Задать `resume_capacity = pause_capacity - 1`, например `acc 50 49`.

Примечания

- В режиме простоя батарея разряжается, хотя и очень медленно. То же происходит с батареей, лежащей на полке.
- В эмулированном режиме простоя батарея обычно удерживает заряд, поскольку устройство работает как «пасс-через». Представьте, что вода льётся в уже полный стакан.


> Как включить «умную зарядку»?

Настройте дневной и ночной профили:

`acc -c a ": day profile; at 6:00 \"acc -s pc=75 mcc= mcv=4100; acc -n 'Switched to day profile'\""; acc -c a ": night profile; at 22:00 \"acc -s pc=50 mcc=500 mcv=3900; acc -n 'Switched to night profile'\""`
